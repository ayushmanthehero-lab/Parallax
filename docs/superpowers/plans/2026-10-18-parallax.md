# PARALLAX Implementation Plan

> **For agentic workers:** Use the task boundaries below and review each independent deliverable before integrating it. The user's instruction authorizes architecture, full implementation, verification, Vercel publication and video production in this session.

**Goal:** Deliver the complete source-grounded coordination application described in `docs/ARCHITECTURE.md`, with a real FalkorDB backend and narrated walkthrough.

**Architecture:** Next.js/React client and Node API communicate with isolated FalkorDB graphs. A bounded deterministic domain verifier and an MCP tool layer support investigator/verifier/coordinator workflows. Every source change, human decision, task, memory and tool call is durable.

**Tech Stack:** Next.js 16, React 19, TypeScript, official FalkorDB client and FalkorDBLite, MCP TypeScript SDK, Zod, Node test runner, Playwright, FFmpeg.

**Spec:** `docs/ARCHITECTURE.md`

## Global constraints

- No mock database is presented as FalkorDB; production requires a configured persistent instance.
- Source interpretations must be reviewed before becoming verification facts.
- A human decision does not complete implementation work.
- Use real MCP calls; label guided and configured-model execution truthfully.
- Derive tenant graph names on the server; version and guard all mutations.
- Never claim an incomplete or bounded search proves unrestricted validity.
- Tests must target behavioral failures, not implementation details or mock call counts.
- No credentials, private account data, or real personal records in code, demo fixtures, logs or exports.

## Review focus

1. A source changes while an older investigation is open: stale results cannot approve the new revision.
2. Two coordinators open or approve the same case simultaneously: one canonical transition and no duplicate tasks.
3. Identically named definitions in separate tenants: no cross-tenant reads, writes or recalled decisions.
4. Partial or unsupported semantics: unknown/incomplete results remain explicit.
5. Restart after decision but before implementation: pending work remains pending and resumes without fabrication.
